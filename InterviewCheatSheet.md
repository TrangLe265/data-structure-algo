## Step By Step through a problem:
1. write down key points of the question
2. double check what are the input and the output
3. what is the most important value of the problem? what is the main goal
4. speak abt first thing that comes in mind
5. show them why this approach is not the best
6. walk through your approacj, comment things and see where you maybe able to break things, any repetition, bottlenecks (like O(n^2))
7. before u start coding, walk thorugh ur code and write down the steps u are going to follow
8. take care of writing readable code from the beginning
9. start writing the code 
10. think abt error check and how you can break this code and tell the interviewer how you would test this code
11. dont use confusing names like i and j 

## Good code checklist:
[ ] it works
[ ] good use of data structure
[ ] Code Reuse/Dont repeat urself
[ ] Modular - make code more readable, maintainable and testable
[ ] less than O(n^2), 2 seperate loops are better than nested loop
[ ] Low space complexity 

## Heurestics to ace the question
- Hash Maps are usually the answer to improve time complexity
- it it's a sorted array, use Binary Tree to achieve O(log N)
- try sorting your input
- hash tables and precomputed information (eg sorted) are some of the best ways to optimize code
- look at time vs space trade off
- follow the advices/tips from the interviewer
